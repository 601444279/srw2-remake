# 战斗画面笔记

给 P5「完整战斗演出」用：原版战斗画面的组成、机体大图、武器特效动画和流程时间。

提取脚本：`node tools/extract-battle-gfx.js`（不带参数 = 全部；`--units` / `--effects` / `--timing` / `--verify` 分别跑；`--weapons 47,51` 只录几把武器调试）。需要 `extracted/states/t4.json`、`e2.json`。输出：

| 文件 | 内容 |
|---|---|
| `assets/original/battle/units/NNN.png` | 机体编号 NNN（十进制）的战斗大图，原版像素、透明背景，123 张 |
| `assets/original/battle/effects/NAME.png` | 一段动画的特效层：去重后的图块（cel）拼成的图，131 张（127 个武器动画 + 4 个爆炸；left-1197b-u058 没有特效画面） |
| `data/battle-sprites.json` | 机体编号 → 图片、原版位置、来源（资源偏移、CHR bank、色板、图块排列、叠色精灵） |
| `data/battle-effects.json` | 武器编号 → 两个方向的动画脚本和录到的动画；动画的关键帧（时长、cel、位置、镜头、色板）；爆炸；流程时间 |
| `data/battle-scene.json` | 游戏运行时用的精简版（`node tools/slim-battle-data.js` 从上面两份生成，提取后要重跑） |
| `extracted/battle/`（不进仓库） | 机体总览 `units-overview.png`、每段动画的整屏关键帧 `stage/NAME.png`（每行 4 帧，256×116，约 20MB）、核对截图 `natural-*.png` 和 `verify.json` |

做法：不自己重写原版的拼图和动画引擎，而是让原版代码在模拟器里画，再按 PPU 状态把需要的层单独渲染出来。机体：t4 存档开战前把 RAM 里的机体编号换成要导出的机体；特效：攻击动画开始前把武器编号换掉。渲染器（`tools/lib/battle-capture.js`）按扫描线记录 MMC3 的 CHR bank 切换、按对象记录 OAM 归属，整屏渲染结果和模拟器画面逐像素一致（见「核对」）。

地址写法同其他笔记：`bank 4 $8E46` 是 8KB PRG bank 4 映射时的代码，`$C000` 起是固定 bank 30、`$E000` 起是 31。资源号见 `docs/notes-units.md` 的资源表（`tools/lib/res.js`）。

## 画面组成

战斗画面（256×240）分两块：

- **上半屏（舞台，y 0–115）**：黑底，左右各一台机体，特效在上面播。**没有地形 / 宇宙背景**：改 `$7411`（地图环境 0–3）和两台机体脚下的地形（16 种）再开战，上半屏都 0 像素变化；战斗设置代码也不读环境
- **下半屏（窗口，y 116 起）**：边框窗口，两边各一行「命中 nn%」「HP 当前/最大」（文字，没有血条），中间是消息（「太勒攻击！」「杰克：发射！」、命中 / 落空 / 击破），左下角是说话驾驶员的 32×32 头像（`docs/notes-portraits.md` 同一套）
- 中断在 y ≈ 116 把 CHR bank 换成窗口用的字库 / 边框，在 y ≈ 125 再换一次给头像

### 上半屏的 PPU 设置

| 项目 | 内容 |
|---|---|
| 背景图案表 | `$0000`（A12 反转，所以 R2–R5 在 `$0000–$0FFF`） |
| R2（图块 `$00–$3F`） | 左侧机体的背景 bank |
| R3（`$40–$7F`） | 固定 `0x35`：特效用的背景图块（光束等） |
| R4 / R5（`$80–$FF`） | 右侧机体的背景 bank（双 bank 机体占 R4+R5；R5 平时是 `0x04`） |
| R0（精灵 `$00–$7F`） | 右侧机体的精灵 2KB bank：叠色精灵 + 它的武器特效图块 |
| R1（精灵 `$80–$FF`） | 左侧机体的精灵 2KB bank |
| 背景色板 | 0 号：窗口（`0F 30 10 00`），1 号：特效（脚本设），2 号：右侧机体（记录 +1–3），3 号：左侧机体 |
| 精灵色板 | 0 号：特效（脚本设），1 号：头像，2 号：右侧机体叠色（记录 +4–6），3 号：左侧机体叠色 |
| 属性表 | 名称表第 0–15 列用 3 号色板，16–23 列 1 号，24–31 列 2 号 |
| 卷动 | 上半屏水平卷动 = `$62`（+ `$60` bit0 选名称表），近身时是 16 / 32 / 48，按布局而定；震屏、远距离的镜头移动都是改它 |

左侧是双 bank 机体时两边对调：左侧机体占 R4/R5（图块 `$80–$FF`），右侧机体挪到 R2（bank 4 `$8EDB`）。所以分辨哪些图块属于哪台机体要看 CHR bank，不能只看图块号。

### 哪台在左、哪台在右

- 机体记录（资源 `0x89`）标志 bit6 = 1 的画在左侧，= 0 画在右侧，和谁攻击无关。我方机体基本是 0（右侧、朝左），敌方是 1（左侧、朝右）
- 战前预测（bank 4 `$880B`）：攻方标志 bit6 → `$E3` bit0。之后 `$E5` = 右侧单位、`$E6` = 左侧单位（bank 4 `$8DFD`）
- **图不翻转**：NES 背景图块不能翻转，每台机体只有一张图，朝向画死在图里。导出的 `side` 是原版画的那一侧，`facing` 是图的朝向。0x9C/0x9D（敌方刚达）和 0x09（我方刚达）用同一张图，所以敌方版本在左侧时是背朝对手的，原版就是这样
- 两台标志相同时（正常游戏里不会出现，改 RAM 才见到）一台照样画到另一侧，位置也不同，图还是同一张

### 布局

战斗画面由画面脚本（资源 `0x20`，和窗口、菜单同一个引擎，固定 bank `$D362`）画出，选哪份在 bank 4 `$8EEC–$8F9B`：

| 资源 0x20 编号 | 用途 |
|---|---|
| `0x50` | 近身（距离 1） |
| `0x51` | 远距离（距离 ≠ 1，`$E3` bit6，bank 4 `$87EF`） |
| `0x49` / `0x4A` | 左侧是双 bank 机体时的近身 / 远距离 |

- **近身**：两台机体在同一屏，左右对站
- **远距离**：两台机体分别画在两个名称表上（世界坐标相距 256 像素左右），开场镜头只看攻方，攻击动画脚本里用 `FD`（卷动）把镜头一路移到守方。射程 > 1 的武器打不到相邻的敌人，所以**远程武器的动画总是远距离布局**；第一关敌方回合里就有一场（拉达K7 用 0x0B 号武器远程攻击刚达）

## 机体大图

### 数据

每台机体由三份资源描述，都以机体编号（资源 `0x86` 下标）为下标：

**资源 `0x89`（bank 4，PRG `0x0AB2A` 起）**：9 字节，标志 bit7 时 10 字节。读取在 bank 4 `$8E46`（右侧 / `$E5`）和 `$8E95`（左侧 / `$E6`）

| 偏移 | 内容 |
|---|---|
| +0 | 标志：bit6 画在左侧；bit7 有第二个背景 bank（+9）；bit5 不明（0xA1–0xA6 有） |
| +1–3 | 背景色板 1–3 号色 → `$0476–$0478`（右侧）/ `$047C–$047E`（左侧） |
| +4–6 | 精灵色板 1–3 号色 → `$0479–$047B` / `$047F–$0481` |
| +7 | 精灵 2KB CHR bank（MMC3 R0 / R1）→ `$04D0` / `$04D1` |
| +8 | 背景 1KB CHR bank → `$04D4`（右）/ `$04D2`（左） |
| +9 | 第二个背景 bank → `$04D5` |

0xB5–0xBF 指向同一条不是机体格式的数据（`00 00 00 00 18 1a …`），没有机体用。

**资源 `0x21`（bank 8，PRG `0x1259B` 起）**：背景图块排列，是画面脚本引擎的字节码（`F0–FF` 指令 + 图块号，图块号加上 `F2` 设的偏移：右侧 `$80`、左侧 `$00`）。大部分机体是 `f3 f9 f9 fd 20 08 f9 40 00 ff` 这类「整块 8×8 顺序排」，少数（太勒等）是不规则排列。**字节码没有逐条解码**，JSON 里的 `tiles.rows` 是引擎实际画进名称表的结果（`--` = 没画，图块号是名称表里的值），`tiles.origin` 是第一格相对图片左上角的位置。

**资源 `0x41`（bank 10，PRG `0x15B02` 起）**：叠色精灵，元精灵格式（下面「元精灵格式」）。右侧机体是 0 号对象、类型 `0x41`，左侧是 1 号对象、类型 `0xC1`（bit7 = 图块号异或 `$80`，即改用 R1 那半）。精灵色板号直接写在数据里（右侧机体 2 号、左侧 3 号），所以叠色精灵也只适合原生那一侧。有的机体（拉达K7）只有一个空精灵，等于没有叠色。

### 导出

- 180 个编号有记录（1–0xB4），按像素去重后 **123 张图**；57 个编号 `sameAs` 别的编号（盖塔各形态的重复编号、敌我同图的刚达等）
- 右侧 98 个、左侧 82 个；双 bank 大型机体 7 个（0x9E–0xA4，最大 111×63、106×93）
- 尺寸 32–111 像素宽、28–93 像素高，大多 45–70 像素见方
- JSON 字段：`side` / `facing`；`screen` = 近身布局时图在原版画面上的左上角（已含上半屏卷动）；`origin` = 叠色精灵对象坐标在图内的位置（特效脚本的锚点，见下）；`bgColors` / `spriteColors` / `bgBanks` / `spriteBank`（含 CHR 偏移）；`layout` / `overlay`（资源偏移和原始字节，叠色精灵另有解码）；`tiles`、`sprites`（实际画出的图块和精灵，坐标相对图片）；`check`

图片 = 背景层（只取这台机体的 CHR bank 的格子，0 号色透明）+ 叠色精灵（这台机体对象的 OAM，0 号色透明，按 OAM 顺序和背景优先位合成）。

## 动画（武器特效、爆炸）

### 数据

- **资源 `0x60`**（bank 8）：攻方在右侧时的攻击动画，以**武器编号**为下标；**资源 `0x61`**：攻方在左侧。选择在 bank 6 `$82D9`（攻击，`$D7`）/ `$83B8`（反击，`$D8`），`$E3` bit0 决定用哪份。192 项去重后 `0x60` 有 60 份、`0x61` 有 50 份脚本
- **资源 `0x62`**（bank 24）：其他动画，击破爆炸是 `0x62#01`
- 脚本坐标以攻方叠色精灵对象的坐标为锚点（`$92/$93` = `$0710/$0720` 或 `$0711/$0721`）
- 解释器：固定 bank `$E832`，指针 `$90/$91`，每帧执行到等待指令为止；`$AA` = 资源号（0 = 没有动画），`$AD` = 编号

| 字节 | 参数 | 含义 |
|---|---|---|
| `00–EF` n | — | 等 n 帧 |
| `F0` i n c… | 2 + n | 写色板缓冲 `$0490+i`（即 `$3F00+i`），c ≥ `$80` 时取 `$03F0+c` |
| `F1` k | 1 | k = 0 上传色板，1 `$FF` bit6，2 色板整体变亮（闪白），3 显示两台机体的叠色精灵，4 隐藏 |
| `F2` i n v… | 2 + n | 写 `$04D8+i`（画面脚本用的参数，如特效背景 bank） |
| `F3` r i | 2 | 执行画面脚本 r#i（用背景图块画特效，如资源 `0x22`） |
| `F4` n | 1 | `$4C` = n（音效） |
| `F5` s v | 2 | 设对象 s 的 x（s bit7 = 设 y） |
| `F6` n | 1 | `$61` = n |
| `F7` sv v | 2 | 中断分屏表（高 4 位选 R0–R5 / 卷动表，低 4 位分屏号） |
| `F8` / `F9` | 7–9 | 建对象：槽号（bit7/bit6 = x/y 从参数队列取）、x、y（F9 相对锚点）、类型、轨道资源、帧轨、x 轨、y 轨 |
| `FA` s | 1 | 删除对象 |
| `FB` / `FC` s | 1 | 对象 bit6 置位 / 清除 |
| `FD` dx dy | 2 | 卷动（震屏、远距离的镜头移动），同时移动 0、1 号对象 |
| `FE` n addr | 3 | 循环 n 次跳到 addr |
| `FF` | 0 | 结束（`$AA` 清 0） |

`data/battle-effects.json` 里每份脚本有 `raw`（读到第一个 `FF`，不跟跳转）和按上表切开的 `ops`。

**对象**（`$0700–$07FF`，16 个槽，每字段 16 字节）：`$0700` 标志（bit7 有效、bit4 隐藏、bit5 背景优先）、`$0710` x、`$0720` y、`$0730` 当前帧（元精灵编号）、`$0740` 元精灵资源（bit7 = 图块号异或 `$80`）、`$0750` 轨道资源、`$0760/$0770/$0780` 帧轨 / x 轨 / y 轨编号。每帧固定 bank `$E8B2` 按三条轨道更新帧号和位置，`$D194` 画成精灵。战斗里 0 号 = 右侧机体叠色，1 号 = 左侧机体叠色，2 号 = 窗口里的头像，特效多用 15 号（`0x0F`）。

**元精灵格式**（固定 bank `$D194`）：`dx dy 首图块`，之后每个属性字节画一个 8×8 精灵，`FF` 结束。属性字节 bit7/6 翻转、bit0–1 色板；bit5 = 下一字节是新图块号，否则 bit4 = 0 时图块号 +1；bit3 = 下一字节加到 x，然后 bit2 = 1 时再读一字节加到 y、否则 y += 8；bit3 = 0 时 bit2 = 1 读一字节加到 x、否则 x += 8。图块号 ≥ `F8` 取 `$06B8 + (n & 7)`。屏幕行 = 对象 y + dy + 1（OAM 的 y 定义）。

**特效图块来自攻方的精灵 bank**：特效对象类型带 bit7（异或 `$80`），实际用的是攻方那半（右侧 R0、左侧 R1）。所以同一份脚本在不同机体上可能画出不同的图（128 个动画对应 107 份脚本），导出时按「脚本 × 机体」录，画面一样的合并。

**用背景图块画的特效**：光束之类用 `F3` 调画面脚本把图块写进名称表（R3 = `0x35` 那个 bank，背景 1 号色板），75 个动画有这种帧。会盖掉机体的格子（原版光束画过去时守方的一部分被切掉）。

### 导出

- 每把武器、每个方向：找装备这把武器、画在这一侧的机体（`data/units.json` 的 `weapons`），逐台录；没有机体的方向不录，只留脚本（`note`）。射程 > 1 的武器强制远距离布局（`layout: "ranged"`），其余近身
- 录法：t4 存档，右侧动画让太勒的位置换成该机体先攻、左侧动画让拉达K7 的位置换成该机体反击；所有命中判定强制落空（不影响画面，只是不让任何一方被击破）
- 191 把武器，录了 317 次，得到 **128 个动画**（107 份脚本）；爆炸 4 个（左 / 右 × 近身 / 远距离）
- 特效层 = 3 号以后对象的精灵 + 相对动画开始前一帧被改掉的背景格子，画在**世界坐标**里（两个名称表并排，512×120，不受卷动影响），0 号色透明
- 每个关键帧裁成最小矩形，相同的只存一次（cel），拼成 `effects/NAME.png`（行宽 ≤ 512）

`anims[NAME]` 字段：

| 字段 | 内容 |
|---|---|
| `cels` | 每块在图里的 `x y w h` |
| `anchor` | 攻方锚点（世界坐标） |
| `camera` | 动画开始时的镜头 = 世界坐标里屏幕左边缘（近身时 = 卷动值） |
| `units` | 攻方 / 守方机体编号和它们在世界坐标里的范围 |
| `keyframes[]` | `start` / `duration`（帧，60 帧 = 1 秒）；`cel` + `x/y`（cel 左上角相对锚点，没有 = 这段没有特效）；`camera`（相对开始时的镜头偏移，震屏 / 镜头移动）；`palette`（和上一关键帧不同的色板项，第一帧相对 `basePalette`；cel 已经按当帧色板着色，这一项主要给闪白等整屏变色用）；`bgChanged`；`overlayHidden`（被隐藏的叠色精灵对象槽） |
| `sounds` | 原版在这段动画里触发的音效 `[帧, 音效号]`（和关键帧同一计数；`--sounds` 在模拟器里记录对 `$4C` 写入 $01–$7F）。原版命中 / 落空之后不另放音效，整场的声音都在动画里；同名武器敌我两侧的音效可能不同（光束枪：右侧 0F、左侧 08） |
| `totalFrames` | 动画总帧数（脚本开始到 `FF`，不含 `FF` 那一帧） |
| `check` | 自检：每个关键帧整屏渲染（模拟每行 8 精灵限制）和模拟器画面不同的像素数；`spriteOverflowKeyframes` = 有精灵因一行超过 8 个没显示的关键帧数 |
| `basePalette` | 动画开始前的 32 色 |

重制版用法：机体图按 `screen`（近身）或 `units[].box`（世界坐标）摆好，按关键帧在 `锚点 + (x, y) − 镜头` 画对应的 cel；`camera` 偏移同时移动背景（两台机体 + 背景特效），精灵特效不跟着动（原版 `FD` 会同时挪 0、1 号对象，就是让叠色精灵跟着背景走）。

## 流程和时间

t4 开战（第 0 帧按下 A），太勒用萨斯剑攻击拉达K7、拉达K7 反击。`data/battle-effects.json` 的 `timing` 有完整事件列表（四种按键方式：`player` 每 20 帧按一次 A，`mash` 每 4 帧按一次，`idle` 只按开战那一次，`rangedPlayer` 强制远距离布局）。60 帧 = 1 秒：

| 阶段 | mash（最快）帧号 | 时长 | 等按键 |
|---|---|---|---|
| 按 A → 黑屏 | 3 | — | |
| 黑屏（画战斗画面） | 3–35 | 32 | |
| 显示、打出「太勒攻击！」「杰克：发射！」 | 35–57 | 约 22（文字打完后） | **等** |
| 攻击动画 `0x60#47` | 57–158 | 101 | |
| 判定、HP 跳到新值、「命中」消息 | 158–170 | 12 | **等** |
| 反击消息 | 177–193 | 16 | |
| 反击动画 `0x61#51` | 193–294 | 101 | |
| 判定、HP、消息 | 294–306 | 12 | **等** |
| 按 A → 黑屏 → 回到地图 | 322–337 | 15 | |

`player` 方式同样的顺序，只是每次等按键多等到下一次按 A（攻击动画 69–170，反击 217–318，地图在 360 帧出现）。远距离布局（`rangedPlayer`）流程一样，开场多 1 帧。回到地图之后的事件（`0x20#37` 等）是脚本继续按 A 在地图上的操作，和战斗无关。

- 进战斗：按 A 后第 3 帧黑屏，约 32 帧（画战斗画面）后显示
- 出场：两台机体直接出现，**没有入场动画**；消息窗口打出「XX 攻击！」「驾驶员：台词」后**等按键**
- 攻击：动画长度看武器，61–272 帧（萨斯剑 101 帧）。128 个动画里 95 个末尾有 60–100 帧的空白（特效播完后停一会儿，常见 `wait 100`）
- **命中 / 落空 / 击破的判定在动画播完之后**（第一次 `rand(100)` 在动画结束后约 6 帧）：命中和落空的上半屏画面逐帧完全一样，**没有闪避或受击动画**，只有窗口里的文字（画面脚本 `0x20#55` 命中、`#54` 落空）和 HP 数字直接跳到新值（没有逐步减少）。命中后等按键
- 反击：消息 5 帧 + 约 11 帧后自动开始反击动画（不等按键），结束后同样显示结果、等按键
- 击破：结果消息后播 `0x62#01` 爆炸（左右、近身 / 远距离都是同一份脚本，56 帧），之后是经验 / 资金消息
- 退场：按 A 后约 5 帧黑屏 15 帧，回到地图

## 变形演出（地图菜单「变形」）

提取：`node tools/extract-battle-gfx.js --transform`（约 1 分钟），写进 `data/battle-effects.json` 的 `transform`，过场帧图在 `assets/original/battle/transform/`；`node tools/slim-battle-data.js` 把运行时要用的部分放进 `data/battle-scene.json`。重制版播放：`src/remake/transform-scene.ts`（设置里战斗演出选「完整」时）。

原版流程（第一关盖塔实测）：地图上放现驾驶员的台词（「龙：开机，到位！」）→ 切到战斗画面放一段演出 → 停在新形态上等按键（窗口里是新形态驾驶员的台词「隼人：盖塔2号点火！变形！」）→ 回地图。流程脚本在 bank 28 `$84BE` 起，`38 02 xx` = 放动画 `0x62#xx`。演出开始前 4–6 帧切 **1 号曲**，回地图时切回地图曲。**演出里没有音效**：`0x62#0B` / `#10` 脚本里没有 `F4`，模拟器里整段演出 `$4C` 只有切歌，没有写过 `$01–$7F`（`--transform` 录的 `pairs[].sounds` 全是空的），原版的声音就是这首曲子。演出画面的布局和战斗不同：舞台到 y = 160，下面才是窗口。

两种演出：

| | 合体（盖塔式三段变形） | 两段变形 |
|---|---|---|
| 动画 | `0x62#0B`，289 帧 | `0x62#10`，97 帧 |
| 机体 | 盖塔 1/2/3（0x02–0x08）、盖塔G（0x73–0x7D）共 30 个组合 | 刚达、刚达Ⅱ、刚达Z、ZZ 等 38 个组合 |
| 画面 | 青色透视网格地面，三架战机依次起飞，冲进星空纵向合体，第 276 帧起整屏加亮（每 7 帧一档）到全白 | 现形态、新形态分别画在两个名称表上（世界 512 宽），镜头先慢后快往一边卷（[帧, 镜头 x]：0/0、31/16、61/32、69/48、73/64、77/80、79/96、81/368…98/432），停在新形态上 |
| 结尾 | 全白时画好新形态，第 306、309、312 帧逐档淡入（亮度托底 3、2、1），315 帧恢复原色 | 动画结束停住 |

- 合体过场按**目标形态**分 6 段（领头的战机不同；盖塔、盖塔G 各 3 段），从哪个形态变来都一样。星空的星星位置是随机的，每次录都不同，所以按每帧的色板和 CHR bank 分组，导出其中一次的逐帧画面（每段约 190 张不重复的帧，256×160，每行 8 张）
- 亮相淡入规则（按色号）：灰色和黑色的亮度刻度比彩色高一级（`0F` = 0，`00` = 1 … `30` = 4），彩色 `x1–xC` 的亮度就是高 4 位；每档把亮度托底到 floor，灰色回到 `(floor − 1)` 行，彩色保留色相、亮度 = floor（最多 3）。重制版把图片像素反查回 NES 色号后套这条规则
- 亮相位置因机体而异（`pairs[].reveal`），两段变形两台机体的世界坐标在 `pairs[].fromAt / toAt`
- 核对：合体 30 个组合，按淡入规则重画的 3 档画面和原版逐像素一致；两段变形 38 个组合，按「黑底 + 两张战斗大图 − 镜头」重画动画期间每一帧，和原版逐像素一致
- 不适用：0x67–0x69、0xA7/0xA8 是敌方机体，放进我方槽位时菜单 / 色板对不上（玩家也不会操作它们变形），没录
- 录法要点：只换 RAM 里的机体编号不够，运行时的形态位（`$77D7` 低 6 位 = 机体表 +0）和盖塔的主驾驶员（形态 1/2/3 = 龙 / 隼人 / 武藏）也要一起换，否则原版菜单算错目标形态、合体动画一直等不到对应驾驶员
- 色板在帧末写进 PPU，下一帧画面才变；`fadeSteps` 记的是画面实际变化的帧

## 核对

1. **渲染器 vs 模拟器画面**：每台机体导出时都把整个上半屏（两台机体 + 所有精灵）按同样规则渲染，和模拟器画面逐像素比较：180 台全部 0 像素不同，等 10 帧后画面不变（已画完）。jsnes 默认把画面四边各 8 像素涂黑（`clipToTvSize`，模拟电视过扫描），这一圈不比；4 台大型机体（0xA0、0xA2、0xA4、0xA5）有 11–69 个像素落在这圈里，导出图保留完整原图
2. **真实战斗截图**（不改 RAM）：t4（太勒 vs 拉达K7）和 e2 起连续结束回合后敌方回合里的 13 场战斗，每场在画好时、第一段攻击动画结束时各截一张，在上半屏搜索导出图的位置逐像素比较：50 次比较（7 种机体：太勒、拉达K7、刚达、乍克、阿波罗A、布达MZ、盖塔1）全部 0 像素不同，位置和导出的 screen 一致（远距离那场的守方在镜头移过去后才在画面里，位置不同），2 次因远距离布局不在画面里跳过
3. **特效自检**：每个动画的每个关键帧整屏渲染（模拟每行 8 精灵限制）和模拟器画面比较，128 个动画 + 4 个爆炸全部 0 像素不同（包括镜头移动、分屏换 bank 的帧）
4. **特效 vs 真实战斗**：上面这些真实战斗里播放的 20 段动画，逐帧算特效层，和导出的 cel + 关键帧（位置、时长、镜头）逐帧比较：20/20 段逐帧完全一致
5. **背景**：改环境 0–3、地形 0–15，上半屏 0 像素变化

## 素材清单（重绘用）

以后统一重绘时按这份清单估工作量（数字由 `data/battle-sprites.json` / `data/battle-effects.json` 统计）。

**机体大图**：123 张不重复的图（覆盖 180 个机体编号），原版像素合计约 40.7 万

| 最长边 | 张数 |
|---|---|
| ≤ 48 | 7 |
| 49–64 | 70 |
| 65–80 | 36 |
| > 80 | 10：0x9E 95×62、0x9F 99×65、0xA0 104×87、0xA1 100×66、0xA2 111×63、0xA3 92×80、0xA4 106×93、0xA5 95×47、0xAB 86×42、0xAD 87×55 |

- 每台一张、一个朝向（我方朝左、敌方朝右）；重绘时如果要两侧都能站，需要另画或翻转
- 同一张图被多个编号共用（盖塔各形态的重复编号、敌我同图的刚达等），重绘按图算，不按编号算

**特效动画**：

| 项目 | 数量 |
|---|---|
| 有动画的武器 | 173 把（191 把里） |
| 不同的动画脚本 | 107 份（同一脚本在不同机体上图块可能不同，导出成 128 个动画） |
| 导出的动画 | 128 个武器动画 + 4 个爆炸（爆炸 4 个是同一份脚本、画面相同，实际 1 种）；近身 89 个、远距离 43 个 |
| 不同的特效画面（cel） | 1471 块（每个动画中位数 8 块、最多 41 块）；最大 512×97（远距离的长光束 / 弹道） |
| 关键帧 | 8174 个，其中 7226 个有特效画面 |
| 总时长 | 19258 帧（约 5.3 分钟，每个动画 61–272 帧） |
| 用背景图块画的特效（光束等） | 75 个动画 |

- cel 里很多是同一个图形在不同位置、不同色板的重复（导弹飞行、光束变色），真正要重画的「图形种类」比 1471 少得多；重绘时可以先按脚本归类，再按 cel 外形合并
- 窗口（边框、文字、HP 数字、头像）不在这份清单里：字库见 `docs/notes-text.md`，头像见 `docs/notes-portraits.md`

## 遗留问题

- 机体排列脚本（资源 `0x21`）和画面脚本引擎的 `F0–FF` 指令没有逐条解码，导出的是引擎画出的结果；重制版直接用 PNG 即可
- 动画脚本 `F7`（分屏表）、`F2`（`$04D8` 参数）、`F6`（`$61`）的具体效果没细查；对象轨道资源（`$0750`，如 `0x69`）的格式没解码，位置和帧都是录出来的
- 音效：`F4` 写 `$4C`，编号和音效的对应没查（音乐 / 音效那边的工作）
- 只录了「有机体装备、画在那一侧」的组合，191 把武器 × 2 个方向里 177 个方向没有机体用，只有脚本。同一武器换到另一侧或别的机体时特效图块会不同（图块来自攻方精灵 bank）
- 修理装置等辅助武器、精神指令、变形 / 合体有没有自己的演出没查
- 两台机体标志相同（同一侧）的情况正常游戏里不会出现，只记录了现象
- 精灵每行最多 8 个：原版每帧轮换 OAM 顺序，超出的精灵会闪烁；30 个动画有这种帧，导出的特效层画出了全部精灵（不模拟闪烁）
- 机体记录 +0 bit5（0xA1–0xA6）的作用没查
- 原版没有入场 / 退场、闪避、受击动画，重制版要加的话需要自己设计（design.md 7 节「表现升级」）
