# 关卡事件笔记

提取脚本：`node tools/extract-events.js`，输出 `data/events/stageNN.json`（每关）、`data/events/ai.json`（敌人 AI 脚本）、`data/campaign.json`（关卡顺序、胜利条件、名册变化）。反汇编器在 `tools/lib/evscript.js`，模拟器对照工具 `tools/verify-events.js`。

地址写法同 `docs/notes-rules.md`：`bank 26 $8192` = 8KB PRG bank 26 映射到 `$8000` 时的地址。事件脚本数据在 bank 26（`$8000`）/ 27（`$A000`）。

## 1. 运行模型

### 关卡号

- `$7411` = 关卡号（0–25）。地图（资源 `$80`）、地图环境（`$81`）、关卡参数（`$82`）、部署块（`$83`）、三张事件表、胜利条件文字、劝降表、格子表全部按它取，**部署块第 n 块 = 关卡号 n−1**（`data/deployments.json` 的 `block` = 第几关）
- 关卡顺序是线性的，没有分支路线：过关时 `71 stageClear` 置过关位图 `$7412–$7415` 的第 `$7411` 位（高位在前），下一关的 `$7411` = 位图从最高位起连续的 1 的个数（bank 10 `$949F`）。剧情分支只发生在关卡内部（标志位）
- 事件表、部署块、地图都有 27 项以上：第 27 张地图、第 27–32 个部署块（每块只有 (13,14) 一个 4 级敌人）、事件表 26–31 项（只有 `DF`）没有关卡号能到达，是未使用 / 调试残留。`bank 29 $AEAE` 有一段把 `$87` 写进 `$7411` 并把计数器 `$741A–` 置 `$40` 的代码，像是调试选关，没有追下去

### 关卡初始化（bank 2 $8107）

清零 `$750C`（回合）、`$750D/$750E`（关卡标志）、各脚本指针 `$751F–$7528`、上次战斗记录 `$752C–$752E`、变量 `$752F–$7536`、单位表；然后读部署块：

| 段 | 格式 | 处理 |
|---|---|---|
| 1 | 到 `FF` 为止的字节 | **跳过不读**。只有第 2、10、25、29、30 块有内容（`00 00 00 00 00 05`），是残留数据 |
| 2 | 6 字节：X、Y、驾驶员、机体、等级、AI | 远调用 `$60`：敌人，放进单位槽 14–31，阵营 `$40`，AI 脚本按 `$AF83` 表 |
| 3 | 同上，最后一字节是 NPC 脚本号 | 远调用 `$5F`：**友军 NPC**，放进单位槽 11–13，阵营 `$80`，行动脚本按 `$ADFC` 表（由脚本控制，玩家不能操作） |
| 4 | 4 字节：X、Y、名册号、0 | 远调用 `$5E`：名册里该号有人且 `$74CC` 高两位为 0（没被击坠、没离队）才出击。名册 0 号固定进单位槽 0 |

原来 `deployments.json` 里第 4 段叫 `order` 的字段就是名册号。

### 三个关卡脚本

脚本是可暂停的协程：每段有自己保存的指针（`$751F/$7521/$7523`），主流程每次调用就从上次停下的地方继续跑，直到遇到「暂停」。

| 表 | 导出名 | 什么时候跑 |
|---|---|---|
| `$93A5` | `start` | 进关时（出击前的剧情），之后**每个我方回合开始**再继续一次（多数关卡开场后就停在 `DF`） |
| `$9721` | `enemyPhase` | **每个敌方回合开始**（我方按「回合结束」之后、敌人行动之前）。大部分援军在这里 |
| `$A49C` | `check` | **每个单位行动结束后**（我方、敌方都算）和每个我方回合开始。胜负判定和过关都在这里 |

模拟器实测（第 1 关）：`enemyPhase` 每回合调用一次；`check` 每个敌人行动后调用一次、我方回合开始调用一次；`start` 每个我方回合开始调用一次。

暂停语义：
- 动作指令首字节 bit7 = 1（导出里 `"pause": true`）：做完后本次调用结束，下次从**下一条**继续
- 跳转指令带 bit7：先跳转再暂停，下次从**跳转目标**继续。常见写法 `turnIs 11; *jumpIfFalse 自己`＝「每次调用检查一次，不满足就等下次」；分支末尾的 `*jump 开头` = 做完这段，下次调用从头再查
- `stop`（`5F`，通常写成 `DF`）：不前进，永远停在这里

### 其他脚本

| 表 | 导出位置 | 用途 / 何时跑 |
|---|---|---|
| `$AF83`（34 项） | `data/events/ai.json` | 敌人 AI，按单位 `$7777`，敌方阶段轮到该单位时跑（`docs/notes-rules.md` 5.2）。不少 Boss 的撤退、台词也写在这里，例如第 1 关凯（AI 2） |
| `$ADFC`（11 项） | `stageNN.json` 的 `npcScripts` | 友军 NPC 的行动脚本，单位槽 11–13 |
| `$B4E9`（11 项） | `persuade` | 劝降。表 bank 28 `$9E03`，每项 3 字节（关卡号、我方驾驶员、敌方驾驶员），序号 = 脚本号。我方该驾驶员与该敌人相邻时单位菜单出现「劝降」（资源 `0x15` #8），选了就跑这段 |
| `$B784`（6 项） | `tiles[].script` | 踩格子：表 bank 10 `$987E`（按关卡号），每项 4 字节（X、Y、驾驶员或 `FF`、值），值 < `F0` 是脚本号，`F0+n` 是商店 n（表 bank 10 `$9743`：问候语资源、强化零件列表）。检查例程 bank 10 `$95A2`（主流程远调用 `$BB`），看的是当前单位 `$CD` 的位置；**模拟器实测**（tools/tile-probe.js，第 21 关出口）：移动到格子上不触发，行动结束选「待命」时才跑格子脚本 |

### 单位槽和名册

- 单位槽 0–10 我方、11–13 友军 NPC、14–31 敌方（字段见 `docs/notes-rules.md` 第 0 节）
- 名册（16 项）：`$743C` 驾驶员、`$744C` 机体、`$745C` 等级、`$74CC` 标志（bit7 被击坠，bit6 转到别的阵营后留下的标记）、`$74EC/$74FC` 经验
- 「当前单位」`$CD`：`select` / `selectCamera` / 劝降时的我方单位 / 正在行动的单位。`self*` 条件、`toAlly` 等动作都对它

### 标志

- `flag n`：n < `$80` 是**关卡标志**（`$750D–$750E`，进关清零，16 个）；n ≥ `$80` 是**全程标志**（`$7416–$7419`，32 个，跨关保留），导出时写作「全程标志 n−128」。第 n 个标志 = 字节 `n>>3` 的 `0x80 >> (n&7)` 位
- 关卡标志 1（`$750D` bit6）也是精神「干扰」的标志，0（bit7）关卡初始化时会看
- 全程标志用来记「劝降了谁」「谁离队」等，影响后面关卡的对话和入队，例如劝降卡尔（第 6 关）置全程标志 7，第 9 关过关时检查它

## 2. 指令表

长度含首字节。`p` = 驾驶员编号（人物编号，名字见 `data/script/names.json` 资源 `0x11`）；驾驶员 8、9、10（龙、欧文、路易，盖塔三人）比较时都当作 8（固定 bank `$CC40`）。`who` 参数：驾驶员编号，或 `FD` 我方、`FE` 敌方、`FF` 任意。

## 3. 导出格式

### `data/events/stageNN.json`

```jsonc
{
  "stage": 1, "index": 0,            // 第几关；index = $7411
  "victoryText": "全歼敌人即胜利。",  // 「目标」菜单里的文字
  "map": 0, "deployment": 1,         // data/maps 下标；data/deployments.json 的 block
  "bgm": {"player":135,"enemy":136},
  "npcDeploy": [...],                // 部署第 3 段（开局就在的友军 NPC）
  "aiScripts": [2,3,...],            // 本关敌人用到的 AI 脚本号（data/events/ai.json）
  "scripts": { "start": {...}, "enemyPhase": {...}, "check": {...} },
  "npcScripts": { "2": {...} },      // 本关 NPC 的行动脚本（部署第 3 段 + spawnNpc）
  "persuade": [ {"pilot":6,"target":43,"script":{...}} ],
  "tiles": [ {"x":6,"y":2,"pilot":54,"shop":3,"greeting":"res-3F#55","parts":[2,3,10,16]} ],
  "summary": { "victory": [...], "defeat": [...], "units": [...], "roster": [...] }
}
```

每段脚本 `{ "entry": "9761", "ops": [...] }`，`ops` 按地址排序，每条：

- `at`：地址（4 位十六进制），跳转目标 `to` 用同样的写法
- `op`：上表的名字；参数用上表的参数名
- 条件带 `"and": true` = 和前一个条件取与；动作 / 跳转带 `"pause": true` = 做完暂停
- 对话：`"dialog": "res-38#2"` 对应 `data/script/res-38.json` 里 `index` 为 2 的一段
- `note`：人名、机体名、对话第一句，只给人看

重制版可以直接实现一个解释器按 `at` 顺序执行（推荐，最准确），规则就是第 1 节和第 2 节。`summary` 是静态分析给出的「这条指令在什么条件下执行」，给不写解释器的地方参考：`when` 是二维数组，外层「或」、内层「且」，`[[]]` 表示无条件。分析只看条件指令，不考虑执行顺序和暂停，复杂关卡（第 16 关）会列出很多组合。

### `data/events/ai.json`

34 段敌人 AI 脚本，同样的指令格式，`usedIn` 是用到它的关卡。

### `data/campaign.json`

`stages[]`：关卡号、胜利条件文字、`victory` / `defeat`（`check` 脚本里走到 `stageClear` / `gameOver` 的条件）、`roster`（所有会改名册的指令及其条件：`join` 入队、`leave` 离队、`joinFromMap` 劝降入队、`mech` / `pilotMech` 换乘）、`persuade`。`initialRoster` 取自 `data/roster.json`（第 1 关开局的 6 人）。

## 4. 胜利条件文字

菜单文本资源 `$20`，第 `关卡号 + 16` 项（bank 28 `$98F8`：`LDA $7411; ADC #$10`）。格式：`FC 20 0F`（调用第 15 项画窗口框）、`FD 40`（窗口属性）、文字、`FF`；`F1` 换行。菜单文本引擎的控制码（固定 bank `$D3F7` 表）只解了用到的这几个：`F1` 换行、`F2 x`、`FC 资源 编号` 调用、`FD x`（bit5 时多 1 字节）、`FF` 结束。失败条件没有文字，按脚本看几乎都是「我方全灭」，另有指定单位被击破（`summary.defeat`）。

## 5. 验证

`node tools/verify-events.js <关> [--turns N] [--wipe N] [--save 名字]`：从开机进关（其他关卡在初始化时改 `$7411`），我方每帧回满 HP，靠连按 A 结束回合，记录事件指令、单位出现 / 消失、名册变化。

- **第 1 关**（正常进入）：开场 `start` 两段对话后停在 `$93F2`；`enemyPhase` 每个敌方回合查一次，**第 11 回合敌方阶段**出现凯 / 莫尼 / 邓肯，位置、机体、等级、对话顺序和导出一致；`check` 在每个单位行动后跑。第 12 回合清掉全部敌人后，下一次 `check`：光标移到 (12,1) → 卡姆入名册 6 号（刚达Z、等级 3）→ 出击（原位被占，放到 (13,1)）→ 对话 `res-38#2` → 过关，过关位图变成 `80000000`
