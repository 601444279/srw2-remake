# 机体 / 武器 / 精神笔记

提取脚本：`node tools/extract-units.js`，输出 `data/units.json`（机体、驾驶员、成长曲线、经验曲线）、`data/weapons.json`、`data/spirits.json`。

下面的「PRG 偏移」都是去掉 16 字节文件头后的偏移；bank 号指 8KB bank。

## 资源表（数据定位的入口）

游戏用「资源号」访问数据表，例程在固定 bank `$FD4F`（`JSR $C10B`，`$18` = 资源号，`$19` = 下标，返回记录指针在 `$18/$19`）：

1. 资源号 × 2 查固定 bank `$F3E2`（PRG `0x3F3E2`）得到 1 个字节
2. 字节高 4 位 = 16KB bank 号（换到 `$8000–$BFFF`），低 4 位 × 2 = 该 bank 开头 `$8000` 处指针表的下标
3. 取到的是一张「下标 → 记录」的 16 位指针表，指针为 0 表示空

| 资源号 | 内容 | 指针表 PRG 偏移 | 项数 |
|---|---|---|---|
| `0x84` | 驾驶员（SP、精神、加成） | `0x9859` | 112 |
| `0x86` | 机体 | `0xA05A` | 192 |
| `0x87` | 武器 | `0xB10D` | 192 |
| `0x88` | 成长曲线 | `0xB827` | 16 |
| `0x11` | 驾驶员名字 | bank 6 | — |
| `0x13` | 机体名字 | bank 6 | — |
| `0x14` | 武器名字 | bank 6 | — |
| `0x15` | 0–3 机体类型名（空/陆/海/？），`0x10+i` 精神名 | bank 6 | — |
| `0x80` / `0x81` / `0x83` | 地图、地图环境、部署（见 notes-maps.md） | | |

文本资源用 `JSR $C102`（A = 0）显示，字符串以 `FF` 结尾。

## 机体表（资源 0x86，每条 16 字节）

记录在 bank 4 的 `0xA1DA–0xA9A9`，192 个编号共用 125 条记录（同一台机体的不同武器版本指向同一条记录）。

| 偏移 | 内容 |
|---|---|
| +0 | bit0–1 类型（0 空、1 陆、2 海，已用类型名资源和盖塔 1/2/3 核对）；bit2 两段变形；bit3 盖塔式三段变形；bit4–5 形态序号；bit6–7 未确认（只有 3 台非 0） |
| +1 | 战斗特殊能力：低 3 位 1/2/5/6 各是一种能力（5 = 25% 几率触发），bit7 另一种（`$E3` bit6 时生效，可能是对光束类的防御）。代码在 bank 6 `$8A86`、`$8B23`，交给战斗规则确认 |
| +2 | 地图 SD 图块号 |
| +3 | 机动（移动力），加成后上限 15 |
| +4 | 速度 |
| +5 | 强度 |
| +6 | 防卫 |
| +7 | 击坠奖金（G），加到 `$743A`，上限 9999 |
| +8–9 | HP（16 位），加成后上限 9999 |
| +10–11 | 击坠基础经验（16 位） |
| +12 | 速度成长曲线号 |
| +13 | 强度成长曲线号 |
| +14 | 防卫成长曲线号 |
| +15 | HP 成长曲线号 |

- 机体名 = 资源 0x13[机体编号]
- 武器：机体编号 < 0x80 查 `0xAF8D + 编号×2`，否则查 `0xB08D + (编号×2 & 0xFF)`，各 2 字节 = 两个武器编号
- 载入例程：bank 4 `$822F`（读记录、按等级加成长）、`$9778` / `$9690`（写进运行时单位表）
- 变形组：形态序号 = (+0 >> 4) & 3，组首编号 = 编号 − 形态序号（bank 26 `$8D92`）。盖塔组（1/5/0x72/0x76/0x7A 号）的组首是全 0 的占位记录，名字只有「盖塔」，具体变形 / 合体规则还没看

### 等级与成长

- 运行时等级从 0 开始存（`$7577`），显示时 +1。部署数据里敌人的参数 b 就是这个值
- 成长曲线（资源 0x88，16 条，每条 25 字节 = 50 个 4 位值，高位在前）：第 k 个值是等级 k → k+1 的增量。数值 = 基础值 + 曲线前（等级−1）个值之和（bank 4 `$981A`）
- 常用曲线：0 = 2,1,2,1…（约 +1.5/级），1 = +2，2 = +5，3 = +10，7 = 2,3 交替，8 = +3，9 = +15；6、10–15 全 0
- 机体基础 HP 成长多为曲线 2/3（每级 +5/+10）

### 经验

- 升级所需：4 条经验曲线指针在 `0xB757`，实际只有 2 条（0、3 → `0xB75F`；1、2 → `0xB7C3`），每条 49 个 16 位累计值，第 i 项 = 从等级 i+1 升到 i+2 的累计经验。曲线号 = 驾驶员掩码字节低 2 位，现有驾驶员全是 0（30, 80, 170, 310, 600…）
- 击坠经验（bank 6 `$84BC`）：基础 = 机体 +10–11 × 敌人显示等级；d = 敌人存储等级 + 6 − 我方存储等级，d < 0 时得 1 点，d 上限 14；经验 = 基础 × MUL[d] / DIV[d]，结果为 0 时给 1。MUL/DIV 在 `0xC627`/`0xC636`，即同级 ×1，每高 1 级 +50%，每低 1 级递减（1/2、1/4、1/6…1/12）
- 我方经验存在 `$74EC`/`$74FC`（按队伍成员号 = `$7737 & 0x0F`）

## 驾驶员表（资源 0x84，变长记录）

部署 / 运行时单位表里的参数 a（`$7537`）就是驾驶员编号。我方第一关：0x36 乔、0x06 大卫、0x0F 由美、0x07 加代、0x08（盖塔，名字 1 字未核对）、0x11 杰克；敌方杂兵 3 = 士兵，2 = 无名字。

| 偏移 | 内容 |
|---|---|
| +0 | 精神点数（SP）基础值 |
| +1 | SP 成长曲线号（杰克是 8，每级 +3） |
| +2–4 | 精神位，24 位，高位在前，第 s 位 = 精神 s（0–18 有效） |
| +5 | 掩码：bit7–3 依次决定后面是否跟「机动、强度、防卫、速度、HP」加成字节；bit0–1 经验曲线号；bit2 未用 |
| +6… | 加成字节（只有敌方首领有，例如 0x16 号 `f8 04 15 08 0f 50` = 机动+4 强度+21 防卫+8 速度+15 HP+80） |

- 载入例程 bank 4 `$81DA`；加成加到机体数值上（`$9778`），我方还会再加队伍成员的改造值（`$746C` 机动、`$747C` 强度、`$748C` 防卫、`$749C` 速度、`$74AC/$74BC` HP、`$74DC` SP，开局为 0）
- **精神没有学会等级**：精神菜单（bank 28 `$9AFC`）只看三件事——驾驶员精神位、当前 SP ≥ 消耗、精神自己的可用条件。SP 不够的精神直接不显示，所以低等级时看起来像「还没学会」。已用改 ROM 的方法验证：把杰克的 SP 设成 250、精神位全开，19 个精神全部出现
- 设计文档说「精神属于机体」，ROM 里是属于驾驶员（参数 a），机体和驾驶员的对应关系来自部署 / 剧情脚本，不在机体表里

## 武器表（资源 0x87，每条 6 字节）

记录在 `0xB28D` 起。

| 偏移 | 内容 |
|---|---|
| +0 | 低 4 位 + 1 = 射程；高 4 位：0 普通，0xE 移动后可用的远程，0xF 辅助（修理装置），0x1 只有 0x98 号一个、含义未知 |
| +1 | 命中 |
| +2 | 命中随距离衰减类型：0 不衰减，1 从距离 3 起每格 −5%（表在 `0xB707`，16 项/类型，第 2 类型更陡但没武器用） |
| +3 | 对空火力加值 |
| +4 | 对陆火力加值 |
| +5 | 对海火力加值 |

- **显示火力 = 机体强度 + 加值**，加值 0 显示「---」（打不到）
- 普通武器射程 > 1 时：移动后不能用、不能打相邻格（bank 4 `$88D7`、bank 28 `$9CC1`）
- 伤害公式起点（bank 6 `$8980`）：强度 + 对应地形火力 − 目标防卫，下限 0；用哪一项火力看目标类型和所在地形。详细规则交给战斗规则那边
- 武器名 = 资源 0x14[武器编号]；同名武器有多个强度版本（例如光剑 1–5 号）

## 运行时单位表（SRAM，每字段 32 格，补充 notes-maps.md）

`X` = 槽位号，我方 0–13、敌人 14–31。

| 地址 | 内容 |
|---|---|
| `$7537+X` | 驾驶员编号 |
| `$7557+X` | 机体编号 |
| `$7577+X` | 等级 − 1 |
| `$75D7+X` | 地图图块号（机体 +2） |
| `$75F7+X` / `$7617+X` | 武器 1 / 武器 2 |
| `$7637+X` | 机动 |
| `$7657+X` | 强度 |
| `$7677+X` | 防卫 |
| `$7697+X` | 速度 |
| `$76B7/$76D7+X` | 当前 HP |
| `$76F7/$7717+X` | 最大 HP |
| `$7737+X` | 我方低 4 位 = 队伍成员号 |
| `$77D7+X` | 低 6 位 = 机体 +0（类型等），高 2 位状态 |

## 名字编码（给剧情文本那边参考）

- 双字节字：`C9 xx` / `CA xx`，单字节：`0x30–0x39` 数字，`0x80–0x99` 为 A–Z 小字母图块，`FF` 结束
- 同一个字在所有名字里编码相同（「情」在友情、情义里都是 `C928`，「力」在毅力、潜力里都是 `C91D`），说明是全局字库编码，不是按字符串单独编的
- 脚本里的 `GLYPHS` 表收录了截图核对过的约 100 个字，能完整解码的名字放进 `name`，其余只放 `nameHex`

## 还没搞清楚 / 待确认

- 机体 +0 bit6–7、+1 特殊能力各值的具体效果（F91 是 2，可能是分身；bit7 可能是光束防御）
