# 地图笔记

提取脚本：`node tools/extract-maps.js`，输出 `data/maps/`、`data/environments.json`、`data/deployments.json`、`assets/original/terrain/`，地图预览图在 `extracted/maps/`。

## 地形图

- 指针表：PRG `0x5A9F`（bank 2，CPU `$9A9F`），27 个 16 位指针，每关一张
- 解压例程：bank 2 `$8066`，把地图解到 SRAM `$7000`（每行 32 字节，宽度之外补 0）
- 压缩格式：宽、高各 1 字节；之后每字节低 4 位 = 地形编号，高 4 位 + 1 = 重复次数，游程可以跨行
- 27 张地图首尾相接（每张的结尾正好是下一张的开头），尺寸 16×16 到 32×32
- 地图外的区域用地形 0（米色格子）显示，光标走到地图边缘时镜头会让出这块区域，原版就是这样

## 地图环境

- 指针表：PRG `0x6D8C`（bank 3，CPU `$AD8C`），27 个，每关一个，实际只有 4 种
- 每条 84 字节：

| 偏移 | 长度 | 内容 |
|---|---|---|
| +0 | 16 | 地形 → 色板号（属性字节形式，色板号 × 0x55） |
| +16 | 16 | 地形效果原始值，`0x64` = 100；第一种环境里地形 5（海）是 `0xD5`，最高位含义待确认 |
| +32 | 48 | 3 组移动消耗，每组 16 种地形，0 = 不能进入；哪组对应空 / 陆 / 海待确认 |
| +80 | 3 | 1 号背景色板的 3 个颜色 |
| +83 | 1 | 地形图块所在的 1KB CHR bank |

- 4 种环境：0 地面、1 地面变体（雪山、冰、河流）、2 宇宙、3 基地内部
- 地形编号 n 的 16×16 图块 = 该 CHR bank 里第 4n..4n+3 个 8×8 图块（左上、右上、左下、右下），在 PPU 里是 `$C0+4n`
- 背景色板：0 号 `0F 30 10 00`、2 号 `0F 30 21 02`、3 号 `0F 37 27 16` 固定（固定 bank `$B2B0` 附近的色板脚本，`80 81 82` 是占位符），1 号来自环境
- 地图区域每帧开头切换到地图专用的 CHR bank，下方状态栏用 MMC3 中断切到另一套，所以帧末读到的 bank 寄存器不代表地图

## 单位部署

- 指针表：PRG `0x701A`（bank 3，CPU `$B01A`），32 个部署块；前 27 个大致对应 27 关，后 5 个很短，可能是援军或剧情事件（待确认）
- 每块 4 段，每段以 `FF` 结束：
  1. 6 字节记录，多数关卡为空（用途待确认）
  2. **敌人**，6 字节：X、Y、参数 a、机体编号、参数 b、参数 c
  3. 6 字节记录，可能是援军或 NPC（待确认）
  4. **我方出击位置**，4 字节：X、Y、出击顺序、保留（0）
- 第一关已用模拟器画面核对：13 个敌人、6 个我方位置全部吻合
- 敌人参数 a 多为 2、3，也有 0x16、0x24、0x28 等；参数 b、c 可能是等级、AI 类型或分组，交给机体数据和战斗规则那边确认
- 生成单位的例程：bank 4 `$8102`，参数在 `$F0–$F5`

## 运行时单位表（SRAM）

字段按「每字段 32 格」排列，第 i 个单位的字段在 `基址 + i`。我方从 0 号开始，敌人从 14 号开始。

| 基址 | 内容 |
|---|---|
| `$7537` | 参数（来自 `$F2`） |
| `$7557` | 参数（来自 `$F3`） |
| `$7577` | 参数（来自 `$F4`） |
| `$7597` | X |
| `$75B7` | Y |
| `$7737` | 初始化为 `$20` |
| `$7757` | 初始化为 `$80` |
| `$7777` | 参数（来自 `$F5`） |

其他字段（HP、精神点数等）在 `$75D7–$77F7` 之间，待机体数据那边确认。

## 其他内存位置

- 地图光标：`$C0`（X）、`$C1`（Y）
- 屏幕画面缓冲：SRAM `$6000–$63FF`（32×30 图块 + 属性表）
