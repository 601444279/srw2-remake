# 头像笔记

提取脚本：`node tools/extract-portraits.js`，输出 `assets/original/portraits/NN.png`（NN = 人物编号十进制，32×32，原版像素、jsnes NTSC 调色板）、`data/portraits.json`，总览图 `extracted/portraits/overview.png`（不进仓库，每行 16 个，按编号排列）。

PRG 偏移都是去掉 16 字节文件头后的偏移，CHR 偏移是 CHR ROM 内的偏移。

## 结论

- 对话框头像和状态画面的驾驶员头像是**同一套数据、同一个尺寸**（32×32），每个人物只有一张，没有表情差分
- 人物编号 = 资源 `0x11` 人物名下标 = 剧情 `F9` 的参数
- 每张头像 = 4×4 背景图块（黑白灰）上叠 4×4 精灵图块（彩色），两层都是 8×8 精灵模式

## 数据：资源 `0x85`

资源表字节 `0x22` → bank 4（`$8000`，PRG `0x8000`）一级指针表第 2 项 → 指针表 PRG `0x9C78`，以人物编号为下标，112 项（0 号指针为 0）。记录在 `0x9D58–0xA059`，每条 7 字节：

| 偏移 | 内容 |
|---|---|
| +0–2 | 精灵 1 号色板的 1–3 号色（0 号色固定 `0F`），程序写到 `$0473–$0475` 再抄到 `$04A5–$04A7` |
| +3 | 背景层 1KB CHR bank（MMC3 R5，图案表 `$0C00`，图块 `$C0–$FF`） |
| +4 | 精灵层 2KB CHR bank（MMC3 R1，图案表 `$1800–$1FFF`，图块 `$80–$FF`） |
| +5 | 背景层首图块（`C0`/`D0`/`E0`/`F0`），经参数队列 `$0500` 交给窗口绘制 |
| +6 | 精灵层首图块（`80`–`F0`），存 `$06BF` |

- 图块号 = 首图块 + 行 × 4 + 列（行优先）
- 背景图块 t → CHR `R5 × 0x400 + (t − 0xC0) × 16`；精灵图块 t → CHR `((R1 & ~1) + bit6(t)) × 0x400 + (t & 0x3F) × 16`
- 一个 1KB bank 正好放 4 个人的一层。主要分布：背景 bank `0x24–0x33`、精灵 bank `0x14–0x23`（各 16 个 1KB），另有背景 `0x10/0x12/0x13` + 精灵 `0x0A/0x0B/0x11`（0x43–0x4E 号），以及 `0x68/0x69`（0x51–0x53 号）。和 rom-notes.md 的「bank 2–6 是头像」一致（8KB bank 2–6 = 1KB bank 0x10–0x37），只有 `0x68/0x69` 在 8KB bank 13
- 背景层用 0 号背景色板 `0F 30 10 00`（黑、白、浅灰、深灰），色板不随人物变化；属性表该处为 0
- 合成：精灵像素非 0 时用精灵色，否则用背景色。精灵优先级在前

### 程序流程

- bank 4 `$9048`（也是远调用 `0x6B` 的目标）：`$18 = 0x85`、`$19 = $EF`（人物编号），`JSR $C10B` 取记录，按上表分发
- bank 29 `$A054`：把 `$04E6`/`$04E7`（+3、+4）写到 `$03EE`/`$03C6`
- 固定 bank `$F9AE`：MMC3 中断在对话框开始的扫描线（约 180 行）按 `$03BC+Y … $03EE+Y` 重设 R0–R5，所以对话窗口区域换成头像 bank，上半屏不受影响
- 显示：背景图块写在对话框名称表第 22–25 行、第 2–5 列（屏幕 x 16–47）；精灵 16 个，OAM y = `$AF`，x = `$10/$18/$20/$28`，1 号色板

`F9` 的分发（固定 bank `$E3D2`）只设了 `$0638`/`$7D` 的标志位，参数怎样进入 `$EF` 没有逐条跟。

## 导出内容

`data/portraits.json` 每项：`id`、`name`、`file`、`width`/`height`、`record`（记录 PRG 偏移）、`colors`、`bg`/`sprite`（bank、首图块、CHR 偏移），以及：

- `sameAs`：和该编号的图完全相同（同图块、同色）
- `blank`：空头像，整张是对话框灰（`0x01 0x02 0x04 0x58 0x59 0x5F`，记录都是 `24 14 C0 80`）
- `mixed`：背景层、精灵层分别借自两个人的记录，拼出来是乱图（`0x5A–0x6F` 米巴、帕依，背景借 0x43 里纳、精灵借 0x13 克娃），应当是没用到的占位

共 111 个编号（1–0x6F），去重后 81 张不同的图，减去空头像和乱图 = **79 张真正的头像**。重复的：0x4F 莫尼、0x50 邓肯、0x54 杰夫、0x55 休斯、0x57 士兵 = 0x03 士兵（头盔）；0x56 假马丁 = 0x0E 马丁。0x51 彼得、0x52 吉姆画的是机械 / 怪物形象（来源 bank `0x68/0x69`）。

对话脚本里 `F9` 用到的编号（`data/script/res-*.json` 的 `face`）全部在 0x06–0x55 之间，都是正常头像。

## 核对

脚本 `tools/emu.js` 开机后连按 A，截图后把两层分别画出来，在屏幕上搜索位置逐像素比较（不比头像外的像素）：

| 画面 | 人物 | 结果 |
|---|---|---|
| 开场对话 | 0x36 乔 | 0 像素不同 |
| 开场对话 | 0x08 龙 | 0 |
| 开场对话 | 0x07 加代 | 0 |
| 开场对话 | 0x0F 由美 | 0 |
| 开场对话 | 0x09 欧文 | 0 |
| 第一关状态画面（太勒） | 0x11 杰克 | 0；导出的 PNG 和截图 32×32 区域整块相同 |

注意：**对话框里背景层比精灵层低 1 行**（模拟器里背景层从 y = 177 开始，精灵层从 176 开始），所以开场截图和导出的 PNG 不是整块相同，是错开 1 行后两层各自逐像素一致。状态画面里两层对齐（都从 y = 184 开始），和导出的 PNG 完全相同。导出按对齐合成，即状态画面的样子，也是画面设计本来的样子（错开 1 行时脸上会漏出白点）。

## 遗留问题

- 对话框的 1 行错位来自中断里改 `$2006` 的分屏时机，是 jsnes 的计时误差还是实机也这样没法确认；重制版直接用对齐的图即可
- `F9` 参数到 `$EF` 的路径、+5 背景首图块怎样写进名称表没有逐条追踪（结果已由截图验证）
- 米巴、帕依（0x5A–0x6F）的乱图和 0x58 吉尔的空头像是否在游戏里出现过没确认；如果剧情里真的用到，重制版需要另外处理
- 战斗画面没有看到头像，没有检查其他画面（如商店、结局）是否有别的头像格式
